# 검색 품질 회귀셋

의미(벡터) 검색이 "코드는 멀쩡한데 결과가 나빠지는" 부류의 회귀를 잡는다. v3.8.8 의
마스킹 별표 수정이 첫 사례 — 정보공개포털 결재문서의 `*******` 가 임베딩 토큰의 절반을
삼켜 top-1 이 77% 에 머물렀는데, 단위테스트로는 잡을 수 없는 종류였다.

## 구성

- `corpus/<id>.md` — 실제 공공문서 50건의 kordoc 마크다운 (정보공개포털 결재문서
  40 + 정책브리핑 보도자료 10, 원본은 `kordoc/bench/corpus`). 5분류 × 10 (보도자료·
  여비수당지급·결과보고·알림요청회신·계획). 라벨은 `manifest.json`.
- `queries.json` — 검색어 44개와 기대 문서. 제목 복붙이 아니라 사용자가 칠 법한
  패러프레이즈("도서관 실내 공기질 측정 결과" → 실내공기질 측정 결과보고).
- `bench.py` — Rust 인덱싱 파이프라인(표 직렬화 → 600/150 청크 → normalize →
  별표 접기 → KoSimCSE int8)을 파이썬으로 재현해 문서 점수 = max chunk cosine 으로
  top-1 / top-3 / MRR 을 낸다. **Rust 쪽(`parsers/mod.rs`, `parsers/kordoc.rs`)을
  바꾸면 여기도 같이 맞출 것** — 재현이 어긋나면 벤치는 거짓말을 한다.

## 실행

```bash
cd harness/search-quality
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/python bench.py          # raw vs current + 게이트 (top-1 ≥85%, top-3 ≥95%)
venv/bin/python bench.py --all -v # 실험 변형 + 미스 쿼리
```

첫 실행이 `chrisryugj/kosimcse-roberta-multitask-onnx` 에서 모델(~106MB)을 `model/` 로
받는다. 맥미니 M-시리즈 기준 변형당 ~20초.

## 기준선 (2026-09-22, v3.8.8)

| 변형 | 청크 | top-1 | top-3 | MRR |
|---|---|---|---|---|
| raw (별표 유지, v3.8.7 이전) | 233 | 77% | 80% | 0.81 |
| **current** | 230 | **91%** | **98%** | 0.95 |
| +결재선 표 제거 | 221 | 91% | 98% | 0.95 |
| +제목 접두 | 230 | 93% | 100% | 0.97 |

current 의 남은 미스 4건은 같은 날 초과근무명령서↔내역서, 응답소 민원 회신↔결과보고
같은 근접 중복이라 사실상 한계. 결재선 표(문서번호·결재라인)는 제거해도 효과가 없다 —
시행문 형식이라 첫 청크에 제목·본문이 이미 들어 있다. 제목 접두는 +2%p 지만 청크
오프셋·스니펫에 손대는 변경이라 보류.

벤치는 벡터 단독이다. 실제 앱은 FTS5 키워드와 RRF 로 합치므로 절대값은 다르고, 여기서
보는 건 파이프라인 변경 전후의 **차이**다.
